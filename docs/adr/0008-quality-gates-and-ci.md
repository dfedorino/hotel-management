# ADR 0008. Качество кода и CI

## Контекст
Критерии 10, 11, 15 оценивают структуру, стиль и тесты; проверки должны выполняться автоматически, а не по договорённости.

## Решение
- `./mvnw verify` запускает: Spotless (palantir-java-format), Checkstyle (правила `.config/checkstyle`), SpotBugs + find-sec-bugs, PMD + CPD, JaCoCo (порог 85% строк, 75% ветвлений), Maven Enforcer (Java 21, Maven 3.9, версии плагинов), ArchUnit-тесты слоёв.
- Конфигурация инструментов — в `.config/`; каждое исключение из правил сопровождается комментарием с причиной.
- GitHub Actions `build.yml` собирает только изменённые модули (`.github/scripts/changed-modules.sh`, `-pl <модули> -am -amd`); при изменении корневого pom, `.config/`, wrapper или CI — всё.
- SonarCloud (`sonar.yml`) — полный анализ ежедневно и вручную: проект один на репозиторий, и частичный анализ Sonar воспринял бы файлы остальных модулей как удалённые.
- Действия GitHub закреплены по SHA коммитов.

## Последствия
- Нарушение стиля, порога покрытия или архитектурного правила ломает сборку локально и в CI.
- Нагрузочные тесты (Gatling) в обычную сборку не входят: им нужна запущенная система (профиль `load-tests`).
